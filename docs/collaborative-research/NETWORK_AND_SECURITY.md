# Network and security boundary

The deterministic demo registers no network, hardware, shell or model capability. References are taken from the two previously pinned public snapshots. The CODATA transcription is BSD-3-Clause and the IANA snapshot is public domain. See the [source manifest and acquisition provenance](../discovery/reference-data/manifest.json).

The separate acquisition adapter needs an externally supplied admission callback, a source key, a reviewed HTTPS path, public literal address, pinned content hash, length and license. It connects directly to that address, bypasses proxy and DNS, validates TLS for the approved hostname, rejects redirects and transfer encodings, and checks both the receipt deadline and content identity. Text is retained as an untrusted excerpt. A caller must enforce a durable one-use grant, source terms, repeated-retrieval policy and audit log before considering any live use. No protected broker is wired to the adapter. PDF or HTML content requires a separately reviewed import path.

Tests cover invalid local endpoints, denied admission, wrong endpoint responses, simulated TLS and connectivity failures, late or revised bytes, malicious source strings, spoofed role output and factory governance regressions. The offline query engine treats source text as evidence. Numerical promotion is limited to known-scope rows with exact parser checks. Source prose cannot add assignments or modify the network policy.

The development Factory is a logical authority boundary. Native kernel device/network isolation remains a prerequisite for expanding to arbitrary workers and model-assisted execution.
