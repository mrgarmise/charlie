## Qualified LAN control decision

Use the existing manual gateway → QualifiedElegooExecutor → existing ElegooMobileBase → TCP100 → sole MotorBridge UART writer. No new motion chooser, competing socket owner or network-triggered authority. The separate implementation uses a **distinct control key**, physically enrolled alongside identity but excluded from the provisioning token record and browser. An opt-in Pi authenticator signs each exact qualified wire frame with HMAC-SHA256, fresh 128-bit connection nonce, monotonic sequence and short device-clock deadline. The device gate independently rejects unauthenticated, stale, altered, replayed, reconnected or unsupported commands; it accepts only bounded N2 pulses (1–200ms, PWM≤35) and N5 pan (20–160 degrees). Explicit STOP and heartbeat need no control key. The device requires UART idle before forwarding, waits for UART TX completion before starting the pulse watchdog, and fails closed on100ms transmit stall. Pulse expiry requests device-side STOP even while heartbeats continue. Pi candidate completion/lease checks account for9600-baud command/ACK serialization and40ms scheduler/poll budget without extending N2 T; these engineering timing bounds still require physical measurement. Existing Pi admission, leases, source binding, exclusive request lock, post-connect recheck, exact ACK, durable uncertainty latch and manual deadman remain necessary. Network credentials confer no control key or Pi grant.

This is an implemented authorizing mechanism, not physical authority or a production deployment. The transport MAC authenticates commands; legacy UART ACKs and video are not authenticated end-to-end, and LAN denial/relay remain possible. It does not turn a command receipt into physical stop evidence. Raw telemetry/query passthrough and continuous drive are intentionally excluded pending separate source-bound qualification. Installed UNO identity and new replacement-specific UART timing, qualified-control key custody, LAN threat review and physical acceptance of the replacement remain blockers. **Historical stock STOP behavior is HANDLED — DONE / OK** based on subsequent extensive user-reported testing, including an actual manual-driving out-of-range event in which the car stopped immediately. This is a closed stock STOP concern, not an outstanding STOP failure.

The existing stationary runtime qualification is not a motion grant. The 2026-11-02 four-direction-floor record remains historically marked NOT QUALIFIED because its test/listening window produced a missing STOP acknowledgement and a final timeout. **Disposition: HANDLED — DONE / OK for the stock car's STOP behavior.** The owner reports the test was poorly designed (STOP sent after its listening period, or similar harness timing issue), and extensive subsequent testing, including a real manual-drive out-of-range immediate stop, established satisfactory STOP operation. Preserve the old failed test as historical test-design evidence; do **not** list it as an unresolved stock STOP defect or require repeating it to close the historical concern. No numerical stopping latency is inferred. Replacement-firmware physical acceptance is a separate prospective requirement.

After these pass, a **CONDITIONAL GO for a separately authorized supervised trial** can be considered on this same board. Preserve stock bootloader, partition table, otadata, NVS and SPIFFS; select exactly one PSRAM target and application offset only after active-slot/security evidence. Do not use a merged “full image” or erase-all. An application-only image might use 0x10000 only if app0 is conclusively selected and permitted; 0x340000 is only the table’s other slot, not an instruction to write it. No flash command is supplied here.

First trial stages: motors physically inhibited by the operator; verify boot/enrollment and UART STOP/Factory/STOP with no control grants; then recovery AP/LAN and reconnect/rollback; then camera/single-owner UI, capture, stream and recognition endurance; finally separate explicit motion authorization through the qualified gateway after independent stop/servo qualification. Abort on failed STOP receipt, reset/boot loop, unknown PSRAM/sensor, corrupted retained partitions, loss of recovery access, image mismatch or camera/resource failure. Record real latency and operator observations. A STOP ACK alone never qualifies physical stopping. On failure revoke grants, inhibit motors and restore the exact saved application under the approved maintenance procedure, preserving evidence and partition contents; full-backup recovery may be necessary only after explicit review. Backup availability cannot defeat encryption, secure boot, revoked download mode or hardware damage. Stock parity cannot be established without eventually running the replacement on the existing board.
