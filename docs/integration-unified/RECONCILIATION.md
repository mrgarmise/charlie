In particular, legacy face tracking still needs qualified actuator migration and witnessed parity; it must not be treated as qualified by this merge. Verified ultrasonic protocol, shared telemetry, a common RP2040 request gateway, exhaustive cross-process source ownership, and physical safety acceptance remain open. Test observations and failures are recorded with the PR. No hardware was accessed or moved. Do not deploy this checkpoint without the remaining architecture, native review and staged acceptance specified in the mission. Preserve existing Pi worktrees, firmware and evidence; rollback consists of stopping this uninstalled integration process and continuing to use the previously validated checkout, without resetting or replacing it.

## STOP uncertainty session latch

The qualified pet executor now latches an unconfirmed STOP or ambiguous pulse exception for the remainder of that executor session. A later STOP ACK does not clear the latch or permit a second start. This is a software defense, not proof of physical stopping, a persistent restart latch, or a replacement for a device-local watchdog/cutoff. The runtime hash changes, invalidating prior runtime-bound grants. Cross-restart requalification and unified legacy-face authority remain open.

## Interim legacy motion restriction

`motion.mobile_base.MobileBase` is the facade used by the existing normal mobile tracker and the ELEGOO face-tracker entrypoints. Its legacy `pan`, `pivot`, `begin_attention_align` and `update_attention_align` methods now raise `LegacyMotionUnavailable` before reaching the transport. These older calls have no independently qualified actuator admission and the chassis pivot has no proven hardware-local expiry. This intentionally makes those legacy movements unavailable until a qualified migration is implemented; acquisition, tracking algorithms and original files remain preserved, but native behavior parity is NOT established. STOP, cancellation, telemetry and the existing independently reviewed bounded calibration/pet pulse paths are retained. This restriction is not an implementation of the requested shared executor, does not enforce a boundary against arbitrary direct use of the low-level Python driver, and is not a substitute for hardware-local safety.

This changes a runtime-hashed file, so any previous runtime-bound mobility grant must be renewed. Do not bypass the restriction with direct driver calls. For rollback in an authorized previously qualified setup, stop the process, use the documented physical cutoff, and return to the separately preserved known-good checkout; no automatic migration or deployment is performed. Further work must implement source-bound qualified chassis and pan requests, migrate the original controllers and establish replay plus witnessed native parity before re-enabling these actions.

## Concurrent chassis executor and STOP admission

The existing `QualifiedMobileExecutor` now admits only one in-flight motion request; a competing request is rejected rather than queued. It independently checks proposal age, bounds and vetoes even when called directly. Its STOP path does not wait for the request lock, signals a per-request cancellation event and rejects requests while STOP is in flight or issued at/before the STOP timestamp. An ambiguous pulse or STOP remains latched. Unit tests use only fake transports, including an in-flight cancellation and competing client. No new transport is opened by these tests.

This is an in-process executor improvement, not a completed application-wide owner: current face-tracking callers are still blocked, an actuator-group pan qualifier and source-bound face request adapter are not implemented, cross-process arbitration and persistent restart fault policy remain incomplete, and STOP timing cannot be guaranteed from these host tests. In particular, the shared socket's send lock and car-local failsafe still require native measurement and independent qualification. The runtime hash changes and prior mobility grants must be renewed.
