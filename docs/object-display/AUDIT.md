Its mobile wrapper deliberately filters cat/dog/person; extend optional label visibility without altering the detector or duplicating inference. Host evidence previously recovered authentic cat/dog-shaped records, including false dog classifications; class names do not establish individual pet identity.

Existing Pi transport is hardware/rp2040_controller.py. It owns serial locking, SESSION/STOP reconnect, PING heartbeat and bounded exchanges. Main application normally has one Deck/body using that controller. Reuse it; don't open a second link in hardware mode. READY is printed after firmware scheduler setup. Serial command buffer is 128 characters (larger CAL exceptions), baud 115200. Existing host connect opens/resets serial and sends STOP/SESSION; do NOT run it during this mission.

Firmware is rp2040/: CommandHandler, protocol whitelist, Display.update at 100ms and main 20ms scheduler. Display WIDTH=17 HEIGHT=7; vendor Pico_ed wordStock supports ASCII letters/digits/space with 5x7 glyphs. Vendor matrix.show(long text) sleeps 50ms per shifted column, so it is UNSAFE for heartbeat/STOP responsiveness. Current Display avoids that by paging <=3 chars. Add a bounded cooperative object scroll using the same glyph table and pixel API. Preserve generic message/feedback/capability/progress ownership and elevate ERROR/NO_BRAIN above observation text. Firmware source changes are allowed, firmware flashing is NOT.

Existing physical authority remains in ServoController; shipped gates/pin assignments are not changed. tools/sync_rp2040.py copies dependencies then main and reboots: inspection only, never invoked. Native Pi hostname does not resolve here; actual installed firmware/display capability/LED rendering, Hailo sharing and physical scrolling remain unverified. This mission performs fake UART/matrix/PWM tests only and supplies a no-device dry run.
