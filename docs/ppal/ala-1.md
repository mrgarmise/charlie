# ALA-1: evidence-directed offline model investigations

ALA-1 supplies an integrated, bounded developmental learning foundation. It does **not** demonstrate improved Robotron perception, score, or general autonomous scientific invention. The real-evidence experiment was contradicted and its candidate was rejected. That is a useful, retained diagnostic finding rather than an inflated success claim.

The governing starting point is the complete [October 2 physical audit](physical-learning-audit.md) and its [companion evidence](physical-learning-audit.json). Four original physical archives were inspected; none was modified. The published processing repair's atomic evidence units, exact forecast recovery, productive checkpoints and conservative restart boundary remain in place. Local `run_camera.py` work was not touched.

## Smallest coherent return path implemented

1. Import an existing episode through its normal immutable E/E importer and context Reflection. Preserve original report/agency hashes and separately reported scores.
2. Consolidate those references into a durable operational learning notebook. Preserve the full RGB saved review subset as content-addressed images; patches are supported without destructive preprocessing.
3. Existing Reflection detects identity/interpretation questions. A general coverage policy considers supervised recognition, unlabeled representation learning, additional examples and clarification.
4. Verified targets permit classification; unlabeled independent RGB coverage permits an investigatory reconstruction trial. Missing prerequisites produce deferral, not invented labels.
5. The existing Executive accepts the exact Reflection proposal and compares its declared value/uncertainty/cost terms. The existing tactical chooser ranks promoted local memories and commits a live prospective **offline** prediction before work starts.
6. A registered, authorized capability executes the exact preserved chooser plan. Small CNN alternatives compare on validation only. Test pixels are not opened during training.
7. The chosen candidate receives one final independent test against a frozen train-only baseline. Its evaluation and forecast resolution are separate preserved evidence. A crash after evaluation reuses that result instead of retesting.
8. Reflection retains the diagnostic finding and generates the next uncertainty question. Existing memory/Evaluator feedback and Executive history survive restart. A failed or unresolved prediction is never score reward evidence.
9. A deployment proposal is recorded; candidates never silently replace production. Missing independent support or separate execution authorization blocks activation.

Charlie here means the implemented **rule-based Reflection, Evaluator and chooser**, not an unseen generative intelligence. Work supplies the generic method/component vocabulary and bounded policies; measured evidence supplies the learning opportunity, prerequisites, selection, result and follow-up question. No manually selected BODY direction, FIRE setting, Robotron appearance rule, expected agency verdict or finished classifier is installed. Broad novel hypothesis/architecture synthesis remains unproven.

## Dataset and evaluation isolation

Examples preserve original hash/path/reference, full RGB pixels, optional crop, metadata, declared identity status and label status. Actions/trajectories remain available through the original agency/context references. This initial importer collects **all saved review JPEGs**, a biased diagnostic subset, not every camera exposure and not an automatically labeled sprite corpus.

Annotations are separate append-only records with explicit source, evidence and supersession. Corrections must supersede the latest interpretation. Predictions, agency beliefs and reconstructed fragments cannot receive verified-label status. Weak/unlabeled examples may support representation investigations; supervised training/evaluation require verified annotations. P1/P2 score readings and provisional SELF are not training targets.

Snapshots freeze examples and labels. Temporal neighbors share episode partitions; identical captures/pixels connect episode groups before splitting. Exact duplicate pixels are deduplicated. Conflicting verified labels, corrupted artifacts and train/test overlap are rejected. Existing evaluation groups keep their roles as datasets grow. New groups default to training; explicit new held-out groups may be supplied without moving old evaluation groups into training.

A new snapshot or additional model version is not another physical experiment. Executive progress distinguishes physical episodes, offline trials and independent offline evidence units. Overlapping test groups are connected and count as one unit. Repeated tests on the same evidence cannot meet independent project-completion criteria.

## Foundry and capability boundary

Optional PyTorch workers support classification and self-supervised RGB reconstruction. Declarative components include one to three convolutional stages, bounded channels, kernels 3/5, ReLU/GELU, supported image sizes, learning rates, seeds, epochs and patience. Generated Python, arbitrary imports and arbitrary architecture execution are rejected. Initial automatic alternatives compare two small component configurations; this is bounded architecture/hyperparameter exploration, not unrestricted model invention.

Training is CPU-only, one thread, deterministic within the recorded runtime, at most 512 examples / 250,000 parameters / 100 epochs. Epoch/validation stopping, cooperative training budgets, independent wall/inactivity supervision and OS CPU limits bound work. Startup grace is separate from useful training budget. Peak RSS is reported; there is **no strict OS resident-memory cap** yet. Cross-version/hardware bitwise reproducibility and Pi training cost are not established.

Every candidate preserves configuration/dataset digest, history, validation selection, runtime version, checkpoint hash and resource report. Immutable tensor blobs plus fsynced atomic checkpoint pointers permit exact interrupted-epoch recovery. Unchanged committed evaluations/resolutions are reused. A forecast completed outside its original horizon remains unresolved; the later diagnostic evaluation is retained separately. No retroactive prospective prediction is manufactured.

The capability registry describes purpose, prerequisites, outputs, cost, limitations and evaluation. It invokes only supported offline methods with explicit inputs and method authorization. Collection/clarification are prospective evidence requests because acquisition adapters do not yet exist. Future trusted capabilities/model families can extend the interfaces; transfer learning, warm-start retraining and generative architecture search are not implemented.

Train-only embedding clustering exposes versioned **opaque** category hypotheses. It adds no labels to datasets and establishes no semantic class or useful discovery. Failed representations may yield uninformative groups.

Shadow activation verifies independent support, artifact identity and separate explicit authorization; rollback is journaled and reversible. Shadow inference returns unverified predictions/representations. No production PPAL model adapter is installed. Candidate selection cannot authorize self-modification or weaken gameplay safeguards.

## Scheduling, interruption and physical boundary

Multiple offline projects can investigate shared evidence serially, subject to available methods, resource/dependency checks and a bounded job budget (default two, maximum eight). This removes a global one-trial restriction from offline investigation. The single physical actuator hook is retained to prevent interference; multiple simultaneous physical conditions would need an explicit interference-aware adapter.

The same Executive project notebook is used by the CLI and opt-in marathon hook. Interrupted/blocked projects retain origins, hypotheses and history. Productive worker deferral retains a pending prediction/checkpoint. New versioned evidence can release an evidence-wait hold; identical evidence cannot automatically retrigger the trial. Existing cumulative completion/attempt-budget policies remain diagnostic, not learned score utility.

`--ala-learning` on the existing developmental runner adds a bounded **between-game** capability stage after ordinary Reflection/Meditation. It requires `--learning-projects`. It is off by default. No PyTorch import, second camera, tracker pass or training happens in live PPAL. Offline entry points refuse an active `play_robotron` process; Linux process inspection and a per-learning-root lock guard normal invocation, not hostile or distributed concurrent writers. A race between separately launched orchestrators is not a distributed resource lease.

The processing supervisor forwards only advancing worker processing units as parent progress. Existing inactivity detection remains; productive budget yields preserve committed work. Confirmed terminal evidence is still required for another START. TIME LIMIT, UNKNOWN, partial processing and SELF loss do not grant restart permission. No armed experiment was run for ALA-1.
