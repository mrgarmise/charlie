# ALA-2 continuation: learning findings can change ordinary operation

Continuation baseline: published `fd01ad2`, clean identical local file tree. This extends the original ALA-2 request; it is not a new project. The earlier [milestone report](ala-2.md) describes the previous boundary. This continuation removes its offline-shadow-only deployment limitation for a tightly scoped, opt-in semantic capability. Actual Robotron score improvement remains unproven.

## Executed return path

Existing Reflection detects perception evidence gaps and verified target coverage. The existing Executive selects a project; the existing Evaluator/chooser selects a prospective model comparison. Foundry compares bounded architectures using validation, then tests the selected model against a train-only baseline on separate episode groups. When independently verified candidate-crop labels are exactly the already supported generic `human`/`threat` roles, the evaluator can additionally produce a semantic admission contract. It selects a confidence admission threshold using validation only, and measures accepted accuracy/coverage on test. Both roles, verified targets, crop inputs, improvement over baseline, complete accuracy on admitted held-out cases and at least 80% coverage are required. This finite admission rule is not a physical safety guarantee.

Existing Reflection generates the resulting operational deployment proposal; no model or gameplay action is manually selected. A fixed integration shadow check tests the exported adapter against the frozen independent evaluation. That check is correlated with the original test, not another independent replication. A separate, externally granted deployment policy authorizes an allowed domain and target. The learner never creates its own authority. Activation is versioned in the existing journal; a frozen manifest retains candidate/checkpoint, evaluation, shadow, authorization, project/prediction lineage and contract. Exported manifests must match the current verified journal activation. Rollback invalidates old exports and revokes automatic reactivation of that proposal.

This path can run from `learning.cycle --deployment-authority POLICY.json` and the existing opt-in between-game path using `--ala-deployment-authority POLICY.json`. A policy supplies a source, target `ppal-semantics`, allowed domains, and optional candidate-specific readiness reference. It is a permission document, not a hypothesis or model design. `--learned-semantics MANIFEST.json` passes the frozen capability to the existing player/marathon; with a granted postgame policy the runner can discover the resulting `semantic-activation.json` before a later game. No new controller or tactical chooser was added. Unconfirmed episode boundaries still forbid a new START.

## Operational adapter and limits

The existing single generic detection/association/agency observation completes first. Optional semantic inference uses existing normalized playfield candidate crops in a one-slot drop-old worker, at 2 FPS, at most 16 crops per submission. Inference never runs on the gameplay thread, takes no camera ownership, and performs no second association pass. Metadata may refine only UNKNOWN detections on still-active, unambiguous physical tracks, for at most 0.75 seconds. Existing taught labels, controlled SELF, track identity, agency thresholds, startup classification and termination are not replaced. Neural player/SELF labels are prohibited.

Tentative semantic metadata may change the objects presented to the existing Forebrain/Hindbrain and therefore an ordinary action. It remains a model interpretation, not a verified identity or training label. Steps and reports preserve the applied semantic evidence, activation ID, errors, drops, crop-copy costs and worker costs. Unavailable/revoked/unsupported models retain the baseline. Rollback is applied when the next episode loads; no unsafe hot swap is performed.

Physical use requires exclusively Robotron-camera-domain evaluation plus candidate-specific offline readiness evidence covering processing recovery, controller release, terminal boundaries, camera ownership and operational cadence. Controlled/synthetic domains cannot authorize physical use. Readiness claims require preserved source evidence and separate authority; this machinery does not manufacture those hardware results. Expensive training stays offline; Torch remains optional for baseline Pi operation. Pi cadence/RSS for the adapter still need measurement.

## Evidence acquisition and annotations

`python -m learning.acquisition --episode EPISODE --output LEARNING_ROOT --max-crops 64` extracts original saved candidate boxes, without a detector/tracker pass, camera or START. Crops retain RGB hashes, original frame and agency hashes, row digest, timestamp, source episode, physical ID and provisional/UNKNOWN metadata. Uniform sampling is over the retained diagnostic subset and is not representative of every camera exposure. One source game remains one physical experiment.

It records a clarification request. To supply explicit observations, use `--annotations ANNOTATIONS.json` instead of `--episode`. The JSON array contains `example_id`, `value` (`human`, `threat`, or abstention), `status`, `source` (`external_annotation` or `independent_measurement`), `evidence`, and optional `supersedes`. UNKNOWN cannot be marked verified. Predictions are not accepted as independent labels. Corrections supersede rather than replace history; ingestion is atomic and exact retry is idempotent. No person has privileged score authority. These role labels do not adjudicate historical scores.

On actual `body-fire-bootstrap-20261001-020552`, extraction produced 64 unlabeled preserved crops, zero new games and clarification request `4a38e320d4d567a09724525953e03ded4e8e3fd2f706bd810ef4f88885fe5949`. No labels or conclusions were invented.
