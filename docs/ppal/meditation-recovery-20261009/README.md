from journal, storage, source-identity and checkpoint integrity failures.

`AWAITING_DEPENDENCY` request. An unchanged rejected hash does not rerun validation
or append new requests/commissions/experience. Interruptions before the rejection,
request or ingestion marker safely retry those same deterministic records.

The normal Executive can then process its context and other eligible work.
Status exposes `rejected_preserved_findings` alongside outstanding requests.
This does not mark existing projects completed or merge temporal investigations.
No new scheduler, error-recovery service or meditation operator was added.
Normal Executive-commissioned meditation uses the same boundary: empty/invalid
errors are now explicitly rejected rather than silently omitted. Its receipt
distinguishes computational completion from finding validation.
Restart acceptance admits only source/context/hash-bound rejections and original
ingestion-bound continuations; replacement delivery must satisfy the exact
retained dependency without creating independent experience. Duplicate rejection
records and forged/unbound records still fail acceptance.

A different artifact may resume this dependency. It must independently pass the
same strict source validator. Append-only continuation binds it to the original
ingestion/context, preserves the rejected bytes and satisfies only this
source-validation dependency. It does **not** independently qualify trajectories
or score. Once accepted, a supplied changed artifact still fails closed; journal,
storage, source mutation and corrupt retained snapshots still stop safely.
