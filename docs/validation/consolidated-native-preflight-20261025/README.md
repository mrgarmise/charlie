# Consolidated native preflight

From the reviewed clean native checkout, one command performs the complete diagnostic without launching gameplay:

```bash
/home/five/Projects/charlie/.venv/bin/python tools/native_robotron_trial.py --preflight --expected-revision "$(git rev-parse HEAD)"
```

The command prints the report directory (fresh `/tmp/charlie-native-preflight-*` by default), a status for each check, and one combined outstanding review list. Retain that directory outside `/tmp` if the evidence must survive reboot. Optional `--output /absolute/fresh/directory` selects persistent storage. Exit 0 means PASS; exit 1 means outstanding checks. `report.json` contains the complete inventory, original evidence paths/hashes/scopes, host batch and review provenance; `summary.txt` is the readable readiness report. No campaign, authority or historical evidence file is written. Existing output directories are refused.

The default campaign is `/home/five/charlie-native-trials/original-marathon-20261025`. It is preserved verbatim. A campaign source mismatch is an actual existing acceptance failure: the preflight cannot edit its freeze or transplant authority. For a later runtime, separately prepare/review a new campaign through the existing infrastructure, retaining the original, and supply `--campaign` to inspect that campaign. This is not a request to reprepare or overwrite the original.

Evidence discovery includes this checkout's `docs/validation`, native trial records and `/home/five/charlie-native-preflight-*` plus prior default `/tmp/charlie-native-preflight-*` reports. Add other historical directories or specific independent review files with repeatable `--evidence-root`. Original JSON scopes and hashes are retained. XML coverage is independently parsed; names, filesystem dates and a green XML alone never establish native provenance or current physical safety. Historical software receipts have no arbitrary expiration. The original launcher still demands all 34 formerly blocked socket cases, with no failure/error/skip. Consolidation additionally requires the four established lease-client cases in its reviewed software receipt. The report distinguishes original socket coverage and lease coverage so missing lease coverage does not imply that the old 153 tests failed or require repeating valid tests.

The retained 153-test native receipt in `/home/five/charlie-native-preflight-wzUxcK3N` contains the original socket selection, but no four lease-client cases. Keep its original scope. A combined receipt, if supplied for review, must preserve actual test results and original native execution provenance; do not write passing testcases or substitute sandbox fixtures for native qualification.

Independent reviews use the existing `runtime_revision`, `host_boot_id`, numeric Unix `reviewed_at`, and `proofs` mapping. Each proof has an absolute original `path` and `sha256`. Complete existing reviews or independently reviewed subsets of the seven proof keys may be supplied. Every reused attestation must still be for the exact runtime, same boot and within the existing one-hour window. Assembly preserves the oldest contributing timestamp, never renews it. Multiple different current proof hashes or a changed current proof fail closed. Stale records remain historical evidence. Arbitrary notes and test XML cannot automatically sign a review.

When all seven independently verified parts and current machine checks pass, `review.json` is assembled and checked by the actual launcher's `verify_review`. It names the exact revision, boot, oldest review time and evidence hashes. No review is issued while required facts are unknown. It is not gameplay authority; campaign authorization and all existing launcher/interlock/deadman checks remain required. `--preflight --run` is refused.

Only the outstanding items need one factual operator review. Reuse original records where their qualification still applies. Current physical emergency stop and who can operate it, installed lease/release identity and independent acceptance, cross-user camera ownership, and current display/focus/framing cannot be certified from a process listing. Where these are unavailable, the report says NEEDS OPERATOR VERIFICATION rather than inventing a pass or demanding a new physical test without evidence that the contract requires one. The current-view acquisition and other existing player gates still run at any separately authorized launch.

The host batch records boot identity, same-user descriptor ownership and its limitations, process/service inventory, thermal/throttle/memory/storage thresholds, device names, and installed client source identity. ICMP is the only controller reachability probe. It opens no controller TCP connection: connecting/disconnecting to some legacy servers itself releases controls. ICMP failure is inconclusive. No LEASE, NEUTRAL, movement, servo, firmware, camera acquisition, policy activation, service stop/start or physical gameplay command is issued.

## Validation and limits

Synthetic review fixtures verify missing/stale/future/wrong-boot/wrong-revision, changed/conflicting/malformed evidence, independent-part assembly, original timestamps/hashes, actual launcher review validity, required socket coverage, persistent output refusal, and byte-for-byte preservation of prepared campaign artifacts. Host fixtures cannot qualify physical safety. The first sandbox run retained 31 passes and four loopback permission errors; a separately approved native device-free rerun exercises those lease sockets. Receipts are retained alongside this document. Real native host readiness is not claimed from Codex's restricted namespace.
